# Propel Dialer — Production Deployment Guide

**Stack:** Backend → Render | Database → Supabase (PostgreSQL) | Frontend → Vercel

---

## Step 1 — Supabase (Database)

1. Go to https://supabase.com → New project
2. Choose a region close to your users (e.g. US East)
3. Once created, go to **Settings → Database → Connection string**
4. Copy two URLs:
   - **Transaction pooler** (port 6543) → this becomes `DATABASE_URL`
   - **Direct connection** (port 5432) → this becomes `DIRECT_URL`
5. Both URLs look like:
   ```
   postgresql://postgres.[ref]:[password]@aws-0-us-east-1.pooler.supabase.com:6543/postgres
   postgresql://postgres.[ref]:[password]@db.[ref].supabase.co:5432/postgres
   ```

## Step 2 — Render (Backend)

### Connect repo
1. Go to https://render.com → New → Web Service
2. Connect your GitHub repo (`Propel-dialer-`)
3. Set **Root Directory** to `backend`
4. Render will detect `render.yaml` and pre-fill build/start commands

Stripe billing has been removed from this deployment (per-client custom setup,
no SaaS billing) — the `STRIPE_*` variables are no longer needed and the
`/api/billing` routes are mounted but unused.

A few more flags are read by the code but intentionally **not** listed in
`render.yaml` so they don't get left on by accident — set them only when you
need them, and unset/`false` afterward:
- `ALLOW_SIGNUP=true` — temporarily enables public self-signup while
  onboarding a new client (Propel is invite-only by default).
- `ALLOW_DEMO=true` — enables the `?demo` login path.
- `INQUIRY_TO_EMAIL` — where landing-page inquiry form submissions are
  emailed; defaults to `braddockjones4@icloud.com` if unset.
- `TWILIO_SKIP_SIGNATURE=true` — emergency off-switch for Twilio webhook
  signature validation; only use if calls break in production and you need
  to isolate the cause.

### Deploy
Click **Deploy**. Render runs:
```
npm install && npx prisma generate && npm run build
npx prisma db push && node dist/server.js
```
`prisma db push` creates all tables in Supabase on first boot.

Your backend URL: `https://propel-dialer-backend.onrender.com`

> **Note:** Free tier services sleep after 15 min of inactivity. Upgrade to Starter ($7/mo) to keep always-on.

## Step 4 — Vercel (Frontend)

1. Go to https://vercel.com → New Project → Import GitHub repo
2. Set **Root Directory** to `frontend`
3. Add environment variables:
   ```
   VITE_API_URL=https://propel-dialer-backend.onrender.com/api
   VITE_SOCKET_URL=https://propel-dialer-backend.onrender.com
   ```
4. Deploy → your app will be at `https://propel-dialer.vercel.app`
5. Go back to Render → update `FRONTEND_URL` to that URL and redeploy

---

## Step 5 — Stripe Setup

1. Go to https://dashboard.stripe.com/products
2. Create 3 products: Starter ($99/mo), Pro ($199/mo), Elite ($399/mo)
3. Copy each `price_xxx` ID → add to Render env vars
4. Go to Stripe → Webhooks → Add endpoint:
   - URL: `https://propel-dialer-backend.onrender.com/api/billing/webhook`
   - Events: `checkout.session.completed`, `customer.subscription.deleted`
5. Copy webhook signing secret → `STRIPE_WEBHOOK_SECRET` in Render

## First Login

Propel is invite-only — the login page no longer has a sign-up option in the UI.
To create the first account:
1. Set `ALLOW_SIGNUP=true` on Render temporarily
2. Call `POST https://propel-dialer-backend.onrender.com/api/auth/register`
   with `{ email, password, name }` (e.g. via curl or Postman) to create the
   account — it signs up as a regular `agent`-role account with a 7-day
   trial, not an admin
3. Set `ALLOW_SIGNUP` back to unset/`false` on Render
4. Sign in from the Vercel URL and start dialing
